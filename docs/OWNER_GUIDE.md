# Owner guide

This platform turns a product idea into a verified application. You are not asked architecture, package, testing, Git, or deployment questions.

## Create a project

1. Open the dashboard.
2. Enter your owner API token.
3. Describe the product in plain language.
4. Optionally attach an existing repository path if work should happen on a copy of that project.
5. Start autonomous development.

You can leave. The platform continues without you.

## Check progress

While work is underway the dashboard shows a simple status such as:

> Building your project  
> Current stage: Runtime verification  
> No action required.

You do not need to read logs, job IDs, or Council transcripts.

## When it is ready

You receive an in-app notification when the project is ready for review. That means:

- implementation finished
- automated verification finished
- a delivery package was prepared from the final verified checkpoint

Ready does **not** mean the application was published or deployed.

## Review the result

On the ready screen you can:

- Open App — a temporary review session from the verified delivery
- Download Source — an archive of the final checkpoint
- Download Build — only when a verified build artifact exists
- Read the verification summary and known limitations
- Look at representative screenshots

Open App is for review only. It is not a live production site.

## Approve

Approve means you accept this autonomous-development result.

Approve does **not**:

- merge to your main branch
- deploy a website
- submit to an app store
- publish a package

The project then becomes complete.

## Request changes

Type one high-level note, for example:

> Make the homepage less busy.

The previous delivery is kept as history. Autonomous work resumes, the application is verified again, and you get a new ready notification.

You do not need to start a new project.
